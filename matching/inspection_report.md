# Matching Pipeline - Initial Inspection and Plan

## 1. CURRENT STATE
Phase 2 (Blocking) is finalized with "Champion v2 (Surgical)" frozen. The blocking system generates candidate pairs efficiently (99.9855% recall on the 10k pilot, with ~1,145 candidates per S1). The project is now ready for **Phase 3: Matching & Classification**. No ML models have been trained yet; the repository currently contains a heuristic rule-based baseline and evaluation utilities.

## 2. WHAT IS ALREADY IMPLEMENTED
- **Pairwise Feature Extraction** (`matching/features.py`): Computes 18 similarity signals (e.g., `exact_core_match`, `levenshtein_name`, `token_jaccard`, `ngram_jaccard`, `digit_jaccard`, `unit_match`) based on the S1 and target dictionaries.
- **Evaluation Metric** (`matching/evaluator.py`): Implements `compute_query_f05` and `compute_macro_f05`, accurately handling singleton logic and weighting precision at 2x recall (beta = 0.5 -> beta^2 = 0.25).
- **Baseline Matcher** (`matching/baseline_matcher.py`): A rule-based scoring engine that sweeps for the best Macro F0.5 threshold.
- **Unit Tests** (`matching/test_matching.py`): Tests for the evaluator and feature extractors.

## 3. WHAT IS MISSING
- **Feature Matrix Builder**: A script to load candidate pairs, join with ground truth to create binary labels (1=Match, 0=Hard Negative), and execute the feature extraction in bulk to create a tabular dataset.
- **ML Training Pipeline**: Script to train a Gradient Boosted Decision Tree (LightGBM/XGBoost) on the feature matrix.
- **Validation Split Strategy**: Group-based splitting on `s1_id` to ensure isolation between train and validation sets, preventing data leakage.
- **Advanced String Features**: e.g., Jaro-Winkler (excellent for name similarity/typos), inclusion ratios, address Levenshtein.
- **Inference Pipeline**: A script to run the trained model over the final `candidate_pairs.tsv` and produce `matching_results.tsv`.

## 4. PROPOSED MATCHING ARCHITECTURE
1. **Data Prep**: Merge candidate pairs with ground truth to assign labels. Hard negatives are naturally supplied by the blocking candidates that do not match the ground truth.
2. **Splitting**: GroupShuffleSplit on `s1_id` (e.g., 80% train / 20% val). No `s1_id` overlaps between splits.
3. **Feature Engineering**: Vectorized application of `matching/features.py` over all candidate pairs.
4. **Model**: Train a LightGBM binary classifier (logloss objective). LightGBM is extremely fast, memory-efficient, and natively handles the tabular signals we extract.
5. **Threshold Calibration**: On the 20% validation set, sweep the probability threshold $T$ to directly maximize Macro F0.5. Because F0.5 penalizes false positives heavily, the threshold will organically tune to a high value (e.g., > 0.70).
6. **Inference**: Predict probabilities on unseen candidates, threshold them, and aggregate `target_ids` per `s1_id` for the final TSV.

## 5. FEATURES TO IMPLEMENT
In addition to the 18 current features, I propose adding:
- **Jaro-Winkler Name Similarity**: Stronger for prefix-heavy matching and minor typos.
- **Token Inclusion Ratio**: `len(intersection) / min(len(s1_tokens), len(target_tokens))` (Catches cases where S1 is a complete substring of a longer target).
- **Address Levenshtein / Jaro-Winkler**: We currently only have address token Jaccard. A raw string distance on the address string can catch formatting differences.
- **Length Ratio**: `min(len, len) / max(len, len)` as a normalized complement to the absolute `len_diff_core`.

## 6. TRAINING DATA / LABEL STRATEGY
- **Positive Labels (1)**: Candidate pairs that exist in `pilot_ground_truth.tsv`.
- **Negative Labels (0)**: All other candidate pairs generated by Champion v2. These act as high-quality "hard negatives" because the blocker already found them to be extremely similar.
- **Split Strategy**: GroupKFold or GroupShuffleSplit by `s1_id` ensures that if `S1-A` is in the training set, all of its candidate pairs (both positive and negative) are in train, and none are in validation.

## 7. EVALUATION STRATEGY FOR F0.5
1. Train the ML model to output well-calibrated probabilities $P(match \mid features)$ using binary logloss.
2. During the evaluation phase, predict probabilities for the Validation set.
3. Use the existing `compute_macro_f05` function in a threshold-sweep loop (e.g., from 0.10 to 0.95 in 0.01 increments) over the validation probabilities.
4. Lock in the threshold that yields the absolute highest Macro F0.5.
5. Apply this locked threshold during inference.
